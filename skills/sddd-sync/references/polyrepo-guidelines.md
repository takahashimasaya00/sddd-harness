# Polyrepo / Multi-Root Workspace Guidelines (`sddd-sync`)

ワークスペース内に複数のリポジトリが存在する **ポリレポ構成** で `sddd-sync` を実行する際の追加ルール。
単一リポジトリ（モノレポ含む）の場合は本ガイドを適用せず、通常の `SKILL.md` の手順どおり進めること。

---

## 1. ポリレポ構成の自動判定と `<docs-repo>` の特定

以下のいずれかに該当する場合、**ポリレポモード**として動作する：

1. **マルチルートワークスペース**: 複数のワークスペースルートが開かれており、それぞれに `.git`（ディレクトリまたはファイル）が存在する。
2. **親フォルダまとめ型**: ワークスペースルート直下に `.git` がなく、直下の子ディレクトリに複数の `.git` が存在する。

**`<docs-repo>`（SSOT）の特定手順**:
1. 各リポジトリ直下の `docs/spec/`（または `docs/adr/`）を確認し、1つのリポジトリに集約されていればそこを `<docs-repo>` とする。
2. 見つからない・複数に分散している場合は、ユーザーに同期先リポジトリを確認する。

---

## 2. Step 1 拡張: 変更コードの特定（複数リポジトリ対応）

ポリレポ環境ではカレントディレクトリで素の `git status` / `git diff` を実行すると意図しない1リポジトリしか見られない（またはGitリポジトリ外エラーになる）ため、以下の手順で差分を特定する。

1. ユーザーが特定のリポジトリ・ファイル・コミット・PRを指定している場合は、その対象リポジトリのみを調査する。
2. 指定がない場合は、ワークスペース内の各コードリポジトリに対してパスを指定して差分を確認する：
   ```powershell
   git -C "<repo-path>" status --short
   git -C "<repo-path>" diff --stat HEAD~1
   ```
3. 変更が検出されたリポジトリが複数ある場合：
   - 関連する一連の変更であればすべて横断して読み込み、差分を整理する。
   - 無関係な変更が混在していそうな場合は、同期対象とするリポジトリをユーザーに確認する。

---

## 3. Step 2〜5 拡張: 同期先と完了報告

- 既存ドキュメントの調査・更新（`docs/spec/`）および ADR 起票（`docs/adr/`）は、すべて `<docs-repo>` 配下に対して行う。
- 仕様書へ追記する際、どのリポジトリの実装・モジュールに関する仕様かが明確になるよう、必要に応じてリポジトリ名を併記する。
- 完了報告のサマリーには「差分を取り込んだ対象リポジトリ一覧」を明記し、コミットメッセージ案は **`<docs-repo>` 向け**であることを明示する。
